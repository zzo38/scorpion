This is the draft of the specification for Live Audio/Video Protocol, and
for the DER-based TV-guide format, and for Movie Decimal classification of
movies and TV shows. It is not a part of the Scorpion protocol and file
format specification; it is an entirely independent one, and a different
program is expected to be used with this specification than the other one
(although these programs might also support other audio/video formats,
TV guide, etc). (There is deliberately no copy protection, etc.)


=== Live Audio/Video Protocol ===

For setting up the connection, a subset of the Scorpion protocol is used
(and the same default port number is used). Send "I" and then a space
and then the full URL and then CRLF. The server must respond with "00 "
and CRLF if OK, or an error code starting with "4", "5", or "6". If it
is OK then the rest works as described below.

Messages sent by either side work in the same way, and are DER format.
(Not all messages are required to be implemented; some are only needed
for special purposes.)

The universal-type messages are:

* Octet string: The audio/video data, using whatever codec (and, if
applicable, the container format) is being used for this stream.

* Integer: Reports the media time code, and/or allows seeking by the
media time code. The units are normally video frames, although this
is not strictly required.

* Generalized time: Reports the current date/time that the sender of
this command believes is the current date/time. For a live stream, this
is the current date/time for the live stream.

* General string: Used for captions, if they are not embedded in the
audio/video stream.

* BCD string: Numeric entry (any characters allowed in a BCD string can
be used and not only numbers). A space or end of string means "Enter",
and if "Enter" is used without being preceded by other characters then
that "Enter" command has no meaning.

* Null: No operation. (This is used merely in case you want to send
something using the connection but there is no command that is needed.)

* Key/value list: Extension. The keys are OIDs and the values can be
any arbitrary types.

The context-specific-type messages are:

* 0 = Stop stream. If this is a live stream, then when it is resumed
later it will not continue from where it left off but instead will
continue from the time when the resume stream command is received.

* 1 = Pause stream.

* 2 = Resume stream.

* 3 = Request current date/time.

* 4 = Error; the current date/time is unknown or cannot be reported for
some other reason.

* 5 = Ping: Has three fields, all optional: Octet string (opaque data
which the other side sends back to identify this ping), Integer (the
media time code at the sender believes is the current time), Generalized
time (the RTC time code that the sender believes is the current time).

* 6 = Pong: Responds to a ping, and has the same three fields. The octet
string is required iff it is present in the ping message, and must have
the same value. The others are optional (whether or not they are present
in the ping message) and specify the time that the receiver of the ping
message believes was the current time at the time it has received the
ping message.

* 7 = Request that the other side should send a key frame.

* 8 = Indicates the end of the current stream.

* 9 = Indicates the end of a stream segment; context-specific message 10
must be used to request the next stream segment. This command is only used
for segmented streaming, and is not relevant for non-segmented streaming.
(Non-segmented streaming is probably better, but segmented streaming might
sometimes be needed for compatibility with HLS.)

* 10 = Request the next stream segment. This command is only used for
segmented streaming. It is OK to request the next stream segment even if
the current one is not yet completed; however, only one such pending
request is possible at once, and further requests are redundant. The
request is cancelled if command 0 or 1 or 2 is used. Note that, in the case
of a live stream that is not being recorded, if you wait for two or more
segments before requesting the next one, then you might miss some.

* 11 = Begin recording at this point. Has one field, which is optional,
and specifies the ID of the recording.

* 12 = End recording at this point.

* 14 = Report the current parameters. (See below about parameters)

* 15 = Specify the desired parameters. It will then report the parameters
which are actually used. If the fields of command 15 are omitted, then it
will only ask for the report of the current parameters without setting it.

* 16 = Change the channel. The field is the channel number, which is a
integer or a BCD string.

* 17 = Select alternate video.

* 18 = Select alternate audio.

* 19 = Select alternate captions.

* 20 = Report info/status.

* 21 = Request info/status.

* 22 = An error in the case that it has received a command which is of a
type that it recognizes and understands but that is not valid according to
the understanding of the receiver.

* 32 = A fatal error which is not due to the client, and which is of the
same kind as the Scorpion protocol errors but which can occur after the
connection has already been successful for some time but now it isn't. Has
two fields, the first being a Numeric string with the two-digit error code
and the second being a Graphic string with the error message. If it is a
temporary error, then there is an optional third field which is a integer
number of seconds to wait before trying again. (The first digit of the
error code must be "4" or "5".)

The parameters are as follows. For specifying the desired parameters, each
one can be a sequence (most preferred to least preferred) or a set (with no
order of the preference), or null if you don't care. For reporting the
parameters, it is a single value, or null if it is not applicable. It is
not guaranteed to support all possible combinations of parameters, and you
are not guaranteed to get the ones that you have requested.

* OID specifying the container.

* OID specifying the audio codec.

* OID specifying the video codec.

* OID specifying the caption format.

* Screen resolution, which is a sequence of two integers.

* Frame rate, which is a integer, in frames per kilosecond.

* Audio sample rate.

* Bit rate, which is a integer. For the desired parameters, any numbers
between the lowest and highest numbers are also considered acceptable.

* Colour depth.

* Audio bit depth.

* Audio channels (mono, stereo, surround, ambisonic, etc).

* Video channels (usually only relevant for 3D TV).

* Interlace/progressive (true=interlace, false=progressive).

* Number of bytes per audio/video data message, not including the DER
header (with the type and length).

* Duration of a segment when using segmented streaming. This can be a
integer, a SI-based time interval, or a real number positive infinity.

* Number of bytes of a segment when using segmented streaming. This can
be a integer, or a real number positive infinity. If it is a integer then
it includes all messages including the headers.

=== TV Guide Format ===

This file contains a key/value list, with the keys being the channel
identifiers and the values being either a channel identifier that it is
a alias of or a key/value list of channel attributes.

Wherever a OID is expected, it can also be a relative OID, in which case it
is relative to 2.25.216572797593463565590631180599022605334. (Some fields
might specify that it does not allow a relative OID, or that it is relative
to something other than 2.25.216572797593463565590631180599022605334. If it
does not specify, then it uses the above specification.)

Wherever a General string is expected, in most cases, bibliographic control
characters are also allowed. Line breaks are allowed in some cases, but in
some cases it is not allowed.

A channel identifier can be one of the following: a integer, a OID, a BCD
string, or a Printable string.


=== Channel attributes ===

...0.0 (Valid date/time) [Generalized time]
  The date/time that this data is valid for.

...0.1 (Time zone information) [Sequence]
  This sequence has the following two fields, both of which are optional:
  time zone database name (Visible string; e.g. "America/Vancouver"), and
  time difference (Integer; number of minutes from UTC).

...0.2 (VCR Plus+ channel number) [Integer]

...0.3 (Display names) [Set of General strings]

...0.4 (Show scheduling) [Sequence of Key/value lists]
  See the below section about show scheduling and show attributes.

...0.5 (RFC 2838 name) [Printable string]
  The "tv:" prefix is not included; only the domain name is included.

...0.6 (Streaming URLs) [Set]
  This is a set of streaming information. Each streaming information is a
  sequence with fields:

  - The URL, which is a Visible string, and can have any scheme which is
  appropriate for streaming audio/video.

  - The parameters sequence in the same format as LAVP command 14. (The
  type is sequence and is not context-specific 14.)

  - (Possibly should add others for e.g. geographic restrictions?)

...0.7 (Has video) [Boolean]
  True if it has video, or false if it is audio only.

...1.0 (Time) [Sequence]
  A sequence with two fields, being the start time (Generalized time) and

...1.1 (Show identification) [Sequence]
  Show identification from least to most specific. Generally, this should

  the case; they may potentially be any types.

...1.2.0 (Movie Decimal identification) [Set of BCD strings]

...1.2.1 (Movie Decimal identification of episode) [Set of BCD strings]

...1.3 (Show name) [Sequence of General strings]
  The name of the show. The order and number of items is the same as for
  field ...1.1; any one which is not applicable may be null. For example,
  this may consist of the name of the show, and then the season name (or
  null if not applicable), and then the episode title.

...1.4 (Original broadcast date) [Generalized time]

...1.5.0 (Description of show) [General string]
  A description of the show. This may include line breaks.

...1.5.1 (Description of episode) [General string]
  A description of this episode of this show, which has the same format
  than the description of the show.


=== Movie Decimal Classification ===

Each movie, TV series, TV episode, etc, will have one or more Movie Decimal
classifications, which is a string of digits. Any string of digits will
correspond to a unique movie/show, although a movie/show might have more
than one string of digits that reference it in the Movie Decimal system.

A user interface may display a menu of what next digits are possible at the
current time and what each one means, therefore allowing understanding what
it means easily; numbers can then be entered using the numbers on the
keyboard or the numbers on the remote control, for quick selection of TV
shows, movies, and classifications. It SHOULD use one of the buttons on the
control to mean a "don't care" digit.

When using DER format, the data type for a Movie Decimal string should be
BCD string for ASN.1X or Numeric string for standard ASN.1.
